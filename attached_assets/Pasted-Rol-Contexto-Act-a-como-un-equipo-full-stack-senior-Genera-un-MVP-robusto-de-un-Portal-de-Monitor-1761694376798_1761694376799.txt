Rol / Contexto
Actúa como un equipo full-stack senior. Genera un MVP robusto de un Portal de Monitoreo y Diagnóstico Financiero-Fiscal para productores (caso Driscoll’s).
Objetivo: detectar riesgos fiscales/financieros (SAT, IMSS, liquidez/endeudamiento), emitir alertas, y ofrecer visibilidad a Driscoll’s con tablero y ficha por productor.
El portal debe soportar: Diagnóstico One-Shot, Monitoreo Recurrente (scheduler), Motor de Reglas editable, RBAC básico (ADMIN/ANALYST/PRODUCER), seed de datos, exportes CSV y adapters mock para SAT/IMSS.

Stack y lineamientos

Frontend: Next.js 14 (App Router) + TypeScript + Tailwind + shadcn/ui.

Backend: Next.js API routes (o Fastify en /server si te es más limpio, pero prefiero API Routes).

DB: Prisma con SQLite en dev y PostgreSQL opcional vía DATABASE_URL.

Auth: NextAuth (Email/Password simple + Google opcional), sesiones JWT; RBAC por roles.

Scheduler: node-cron o equivalente para ejecuciones semestral/anual (usa RRULE simple mock mensual en demo).

Infra local: scripts prisma migrate/seed.

No incluir: Docker, Storybook, CI/CD, pruebas e2e (puedes agregar 2–3 tests unitarios ligeros si lo consideras útil).

Calidad: ESLint + Prettier + simple logger.

Modelado (Prisma)

Crea estas entidades mínimas, con migraciones y seed:

User { id, name, email (unique), role: ADMIN|ANALYST|PRODUCER, hash, isActive, createdAt }

Producer { id, displayName, rfc (unique), zona, contacto, email, phone }

LegalEntity { id, producerId (FK), rfc, tipo: MORAL|FISICA, poderesVigentesAt, status }

Ranch { id, producerId (FK), nombre, zona, hectareas, empleados }

Crop { id, ranchId (FK), tipo: FRESA|FRAMBUESA|ARANDANO|MORA, temporada }

FinancialSnapshot { id, legalEntityId (FK), periodo (YYYY-MM), liquidez, endeudamientoPct, ingresosAnuales, egresosAnuales, notas }

ValidationTask { id, legalEntityId (FK), tipo: SAT|IMSS|FINANCIERA|LEGAL, modo: ONE_SHOT|RECURRENTE, estado: PENDIENTE|OK|RISK|FAIL, executedAt, payloadIn JSON, payloadOut JSON }

Alert { id, legalEntityId (FK), ruleCode, severity: LOW|MEDIUM|HIGH, message, createdAt, resolvedAt? }

Rule { id, code (unique), name, description, severityDefault, isActive, evaluatorType: THRESHOLD|BOOLEAN|CUSTOM, config JSON }

AuditLog { id, actorUserId (FK), action, targetType, targetId, at, metadata JSON }

Incluye índices útiles (por rfc, createdAt, severity).

Motor de Reglas (RuleEngine)

Implementa un RuleEngine configurable leyendo Rule + config. Reglas iniciales:

SAT_OPINION_NEGATIVA → HIGH si SatAdapter.status = "negativa".

IMSS_SUSPENSION → HIGH si ImssAdapter.status = "suspendido".

ENDEUDAMIENTO_ALTO → HIGH si snapshot.endeudamientoPct > 35.

LIQUIDEZ_BAJA → MEDIUM si snapshot.liquidez < config.umbral.

PODERES_VENCIDOS → MEDIUM si poderesVigentesAt < now().

Debe permitir activar/desactivar reglas y ajustar config sin re-deploy.

Adapters externos (Mock)

Implementa Adapter Pattern con interfaces y mocks deterministas:

SatAdapter.getStatus(legalEntity) → { status: "positiva"|"negativa", vigencia: ISO }

ImssAdapter.getStatus(legalEntity) → { status: "activo"|"suspendido" }

FinAdapter.getSnapshot(legalEntity|producer) → { liquidez, endeudamientoPct, ingresosAnuales, egresosAnuales }

Los mocks pueden derivarse del RFC (hash simple) para reproducibilidad. Llaves .env simuladas: SAT_API_KEY, IMSS_API_KEY.

Flujos clave

Diagnóstico One-Shot (por productor o razón social)

Acción: botón “Diagnóstico One-Shot” en ficha o lista.

Crea ValidationTask (SAT, IMSS, FIN), invoca adapters, persiste payloadOut.

Ejecuta RuleEngine, crea Alert según resultados.

Actualiza semáforo (estado más grave).

Monitoreo Recurrente (scheduler)

node-cron: RRULE demo mensual (para mostrar funcionamiento), configurable (semestral/anual).

Re-ejecuta validaciones para cohortes (por zona o lista).

Si cambian métricas/estatus → nuevas Alert.

Bitácora en AuditLog.

Gestión de Alertas

Listado con filtros por severidad, tipo, fecha, zona.

Acción: “Resolver” (marca resolvedAt).

Exportar CSV de alertas por periodo (endpoint dedicado).

API (ejemplos)

POST /api/validation/run body: { legalEntityId, tipo, modo } → crea ValidationTask, ejecuta adapters, RuleEngine, retorna alertas.

GET /api/exports/alerts.csv?period=YYYY-MM

GET /api/rules POST /api/rules PATCH /api/rules/:id

POST /api/rules/test body: { ruleId, snapshotId } → resultado evaluación
